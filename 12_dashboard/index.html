Two ways of asking whether a data type can be predicted without its own data. Context-free: the untrained model gets an entity with every observed value of that type removed (eval prompts never carry other types, so this is its prior alone). Leave-one-type-out (LOMO): a LoRA trained on every type except one, then asked about the held-out type with that entity's own values in the prompt, as usual. The "fine-tuned reference" is the matched all-data LoRA on the same finished 740-step schedule (sid_full where it is missing). The Xenium hold-out eval is still running.

Dropping bulk RNA vs dropping flow, type by type

Both hold-out adapters ran the same finished 740-step schedule. Bars left of zero: the type does worse when bulk RNA is removed than when flow is removed. Read with care: removing TCR, which shares no genes with scRNA or Xenium, moves them just as much (see the off-target chart), so large swings on scRNA and Xenium are most likely run-to-run training noise, not transfer from bulk RNA.

Off-target effect of each hold-out

Hold-out adapter minus the all-data LoRA trained on the same finished schedule, per type, with a paired 95% bootstrap interval over prompts. Coloured where the interval excludes zero. Left of zero: removing that data type from training hurt this type. The intervals cover eval sampling only, not run-to-run training variation: scRNA and Xenium swing by 0.1–0.2 whichever type is removed, so treat those swings as noise until repeat seeds exist.

The classical counterparts of the Glimmer hold-outs, on every numeric type, best method per setting. S1 type absent: nothing of the type anywhere, other types only (matches context-free Glimmer); only gene-linked types can do better than a constant.
