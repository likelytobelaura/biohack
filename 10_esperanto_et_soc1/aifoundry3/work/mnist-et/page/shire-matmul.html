Inside one shire: how 32 cores train on 32 rows

Each of the 32 shires takes 32 of the 1,024 rows in a training step, one row per core. The cores never talk to each other directly. They talk through the shire's 2.5 MB scratchpad, which holds the weights and every intermediate result, and they take turns with barriers.

The shire and its scratchpad

A core writes shared data with fswg.ps, a vector store that skips its private L1 cache and lands in the scratchpad. To read shared data, a core first evicts those lines from its own L1, then loads them through the L1. The L1s are not coherent, so this rule is what keeps every core's view correct.

Buffer sizes are from mnist_args.h, drawn to scale. The weights take 336 KB. The layout starts 256 KB in (offset 0 faults) and, with transposes, momentum, gradients and staging, ends exactly at the 2,560 KB limit.

One training step: who owns what

The step alternates two kinds of phase. In a row phase, core j owns row j and does elementwise work on it: ReLU, softmax, masking. In a matmul phase, core j owns output tiles instead, and reads rows that other cores wrote. A shire barrier separates every phase, so nobody reads a row before it is finished.

The layer-2 matmul, tile by tile

The biggest phase, G2, computes Z = A1 · W2 for the shire's 32 rows: a 32×256 by 256×256 product. The output is cut into 8-row × 16-column tiles, 64 of them, and core j takes tiles j and j + 32. Highlighted below is core 5: it reads 16 rows of A1, one 16-column panel of W2, and writes two tiles of Z.

Drawn to scale, one unit per element. W2 is stored as 16 column panels (each 256 rows × 16 floats, contiguous), so the B row a core needs at each step is one 64-byte line.

Inside one tile: the vector inner loop

For each of the 256 values of k, the core loads one row of its weight panel, broadcasts the eight activations A1[r][k] of its tile's rows across all eight lanes, and does 16 vector multiply-adds into 16 accumulator registers. That is 128 multiply-adds per k.

  • flw.ps ×2Load the next row of the W2 panel (16 floats, one cache line) into the spare pair of B registers, one step ahead of use.
  • fbc.ps ×8Broadcast A1[r][k] for the tile's eight rows, each into all eight lanes of its own register.
  • fmv.x.w ×10Touch each freshly loaded register once before using it, the workaround for silicon erratum 1.29.
  • fmadd.ps ×16Accumulator for row r, columns 0–7 and 8–15: acc += A1[r][k] × W2[k][c..c+7].

Measured: about 440 cycles per two values of k, or 0.58 multiply-adds per cycle per core. The tensor unit, which this kernel does not use yet, does about 7.7.

What leaves the shire

Only gradients and weights, once per step. Each 16×16 weight block has one owner shire. The owner pulls that block's partial gradient from all 32 shires with TensorLoadL2Scp, a copy engine that reads another shire's scratchpad directly, sums the 32 copies and updates the block. Then every shire pulls the updated blocks it does not own. Chip-wide barriers separate the stages.
